# llama.cpp-gfx906

What this fork changes against upstream llama.cpp, how to run it, and what each change measured. All numbers are from one AMD Instinct MI50 32 GB (ROCm 10.1, power limit 178-240 W) with Qwen3.8-27B and its MTP draft head (`--spec-type draft-mtp --spec-draft-n-max 3`). With MTP every step verifies about 4 tokens in one pass (pp4); four requests at once verify about 16 (pp16).

## Running it

The image `ghcr.io/rayakame/llama.cpp-gfx906:<upstream tag>-<version>` starts `llama-server`:

```sh
docker run --device /dev/kfd --device /dev/dri -v /models:/models -p 8080:8080 \
  ghcr.io/rayakame/llama.cpp-gfx906:b12230-v0.7.0 \
  -m /models/Qwen3.8-27B-Q4_1.gguf -ngl 99 -fa on -lm dio -c 131072 -b 2048 -ub 2048 \
  --spec-type draft-mtp --spec-draft-n-max 3 --spec-draft-p-min 0.3 --host 0.0.0.0 --port 8080
```

Always pass `-lm dio`; mmap of the model file hangs on this stack.

## Release benchmarks

Every release is measured against upstream's newest release and mx-llama.cpp's newest commit, both built from this
fork's Dockerfile (same ROCm, same flags), so that only the source differs. `scripts/gfx906/bench/bench.sh` runs on
the card's Docker host:

- six Qwen3.8 27B files: Q4_1, Q4_K_M, Q8_0, UD-IQ3_XXS, UD-Q4_K_XL, UD-Q6_K
- every file on every image in the order A B C C B A, so that drift over the hours falls on all builds alike
- `llama-bench` pp4, pp8, pp16, pp512, pp2048 and tg128, 5 repetitions, median of all samples
- `llama-server` with MTP (`--spec-type draft-mtp --spec-draft-n-max 3 --spec-draft-p-min 0.3`, 32k context, four
  slots): three requests at temperature 0 one after another, then four at once (`client.py`); the one-user speed
  is the mean of the three requests' medians
- before every run the chip cools to 50 °C; the power cap is held at 205 W and the fans run at full speed for the
  whole run, and a run whose cap read anything else is left out and named

`report.py` turns a run into the tables. The images' digests and versions are kept with the results. Every release's tables are in [docs/benchmarks](benchmarks/).

## Memory leak test

`scripts/gfx906/leaktest/leaktest.sh <image> <model.gguf>` sends the same 200 requests of changing length twice
with `hipshim.c` preloaded, which counts the HIP graph calls. More than 10 MiB of card memory per 100 requests in the
second pass is a leak. ROCm's `hipGraphExecUpdate` leaks about 1 MiB a request; this fork re-instantiates instead.

## Quantizations

Work in progress: the goal is the same treatment for every quantization of Qwen3.8 27B from Q3 up that fits the card. Today the mat-vec commits cover Q4_0, Q4_1, Q4_K, Q5_K, Q6_K and Q8_0 (Q4_0, Q4_1 and Q8_0 up to 16 columns), and at 2..8 columns also Q2_K, Q3_K, IQ2_S, IQ3_XXS, IQ3_S, IQ4_NL and IQ4_XS; the matrix-kernel commits cover Q4_0, Q4_1, Q8_0, the K-quants and the IQ types of the UD files.
